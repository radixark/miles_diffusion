# π₀.₅ supervised fine-tuning

Native π₀.₅ uses miles' existing SFT loss, Ray actors, FSDP2, gradient checkpointing
and DCP checkpoints. Install the normal miles dependencies: the training model
needs neither OpenPI/LeRobot nor a patched Transformers installation. Training
and SGLang inference may use separate environments. Supported: full-parameter
FP32, DP/FSDP, sequence-parallel-size=1. LoRA, mixed precision and online serving
weight updates are not supported by this backend.

## External adapter and model inputs

Dataset readers, simulators, robot clients, tokenization and source-specific
transforms belong outside this repository. Supply an importable rollout hook via
`--rollout-function-path`. As in the existing SFT hooks, return samples with each
`Sample.train_metadata["sft_pair"]` containing an unbatched
`{"observation": observation, "actions": actions}` dictionary. The shared
`sft_rollout.convert_samples_to_train_data` delivers these pairs to the actor.
Use the normal resumable data-source cursor when iterating a manifest; the core
imposes no dataset index key or source file format.

The default π₀.₅ prepare hook validates this contract before device transfer:

| Field | Shape / type | Meaning |
|---|---|---|
| `observation.image` | Camera-name dictionary | Exactly `base_0_rgb`, `left_wrist_0_rgb`, `right_wrist_0_rgb`, processed in this order |
| Each RGB image | `[224,224,3]` or `[3,224,224]` | `uint8` in `[0,255]`, or finite `float32` in `[-1,1]`; resize/letterbox before delivery |
| `observation.image_mask` | Same camera keys, scalar bool each | True for an available camera; provide a valid dummy image and False for an absent camera |
| `observation.tokenized_prompt` | `[T]`, int32/int64 | `1 <= T <= model.max_token_len`; IDs within the checkpoint vocabulary |
| `observation.tokenized_prompt_mask` | `[T]`, bool | True for valid text/state tokens, False for padding |
| `observation.state` (optional) | `[action_dim]`, finite float32/float64 | Adapter context only; the π₀.₅ forward does not embed this vector |
| `actions` | `[action_horizon,action_dim]`, finite float32 | Already aligned, normalized and padded model-space action targets |

Within a microbatch, corresponding image layouts, token lengths and observation
keys must match so they can be stacked. Use the checkpoint's tokenizer, prompt
format, special tokens, padding and state-token convention; if state is encoded
in the prompt, the adapter must do so before supplying tokens. Passing a raw
state vector alone does not condition this model on state. The core cannot infer
or validate the semantic correctness of a tokenizer or action representation.

The adapter owns camera mapping, temporal alignment, action units, coordinate
frames, absolute/delta representation, episode-end handling, normalization and
zero-padding of unused action dimensions. The loss includes padded dimensions;
there is no implicit action mask. Inference must use the same input transforms
and the matching inverse action transforms before commanding a robot/simulator.
The core retains training image augmentation, noise/time sampling and velocity
prediction; supply images before stochastic augmentation.

## Weight bundle

`--hf-checkpoint` points to `model.safetensors` (OpenPI-compatible parameter names
and tied-weight metadata) and `miles_pi05.json`:

```json
{
  "version": 1,
  "model": {
    "pi05": true,
    "paligemma_variant": "gemma_2b",
    "action_expert_variant": "gemma_300m",
    "action_horizon": 10,
    "action_dim": 32,
    "max_token_len": 200
  },
  "data_adapter": {"id": "my_adapter.v1"},
  "assets": ["normalization.json", "transforms.json"]
}
```

`data_adapter` is optional opaque metadata. Record the tokenizer/version, state
encoding, action convention, normalization, padding and inverse-transform version
there or in declared assets. `assets` lists required files relative to the bundle's
`assets/` directory; missing declared files fail loading/export. It can be omitted
for a model-only bundle. External adapters must declare the files their transforms
require and validate their contents. No particular statistics format is imposed.

Export preserves all metadata and the entire optional `assets/` directory. Older
version-1 bundles remain readable: legacy `config_name` and dataset fields are
preserved without interpretation, and existing assets are copied even without a
manifest. The adapter remains responsible for validating legacy transform assets.

## Train, resume and export

Use the existing `train_sft.py` entry point with your normal batch, optimizer,
GPU, manifest and checkpoint arguments, plus:

```text
--diffusion-model-family pi05 --diffusion-task vla
--train-only --train-backend fsdp --loss-type sft_loss
--update-weight-target-module policy --fsdp-supervised-streams action
--fsdp-master-dtype fp32 --fsdp-reduce-dtype fp32 --diffusion-forward-dtype fp32
--diffusion-guidance-scale 1 --gradient-checkpointing --log-loss-sigma-bucket 0
--rollout-function-path my_adapter.rollout.generate_rollout
--custom-prepare-train-batch-path miles.backends.fsdp_utils.models.pi05.loss.prepare_batch
--custom-loss-function-path miles.backends.fsdp_utils.loss_hub.sft.sft_loss_formula
--custom-convert-samples-to-train-data-path miles.rollout.sft_rollout.convert_samples_to_train_data
--custom-rollout-log-function-path miles.rollout.sft_rollout.log_rollout_data
--n-samples-per-prompt 1
```

The prepare hook constructs `x_t = t * noise + (1 - t) * actions` and the target
`noise - actions`. Shared SFT loss and the actor handle reduction and gradient
accumulation. FSDP wraps invoked SigLIP blocks, Gemma MLPs and conditional norms;
shared embeddings stay in the root group. No simulator runs inside the loss.

Resume with the original bundle, `--load` and a cumulative `--num-rollout` target.
The shared loader restores model, optimizer, scheduler, RNG and dataset cursor;
explicit resume fails on missing/corrupt required state. `--no-load-optim` skips
optimizer state but restores an existing scheduler; `--no-load-rng` skips RNG.

Export using the existing DCP checkpoint:

```bash
python scripts/export_pi05.py --ckpt-dir /data/run/iter_0000010 \
  --base-bundle /data/pi05-bundle --out /data/pi05-export
```

Export validates weight keys, shapes and tied aliases, preserves adapter assets,
and writes SGLang-compatible `config.json`. It refuses to overwrite an output.
SGLang produces model-space actions; interpretation belongs to the external adapter.
