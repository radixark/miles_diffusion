# π₀.₅ / LIBERO supervised fine-tuning

This adapter runs the official OpenPI `PI0Pytorch` model and flow-matching loss
through miles' existing SFT entry point, Ray actors and FSDP2 backend. It supports
full-parameter fp32 training, checkpoint resume, export to safetensors, and
LIBERO evaluation using SGLang's native π₀.₅ action endpoint. LoRA, sequence
parallelism, mixed precision and online train-to-server weight updates are not
supported by this recipe.

## Environments

Use separate training and SGLang environments: OpenPI needs patched Transformers
4.53.2, while the serving runtime uses a different Transformers version.
`requirements-pi05-train.txt` records the tested direct dependencies for an
isolated Python 3.12 training environment; it does not replace miles' default
requirements or provide a complete lockfile.

Install miles, OpenPI and its `openpi-client` package without resolving their
conflicting default requirements. Install the pinned LeRobot dependency, and
apply OpenPI's `transformers_replace` patches to the isolated environment.
The launcher checks the Transformers version and patch before starting training.
The adapter was exercised with these upstream revisions:

- OpenPI: `215abfb217dbac7d5f1273282331b9b1866c0479`
- LeRobot: `0cf864870cf29f4738d3ade893e6fd13fbd7cdb5`
- SGLang: `6393e66b8649b4e6e22f2d94a933e69059192900`

The simulation environment also needs LIBERO, robosuite 1.4.1 and MuJoCo 3.1.6.
Use `MUJOCO_GL=egl` on headless Ubuntu or `cgl` on macOS. Install LIBERO from its
checkout; `--libero-checkout` below creates an isolated, noninteractive config.
Store dependency caches, datasets, temporary files and checkpoints on a suitable
persistent filesystem. The examples use `/data`; adjust it for your environment.

## Prepare the base model and data

Start from `gs://openpi-assets/checkpoints/pi05_base`. Convert the downloaded JAX
checkpoint using OpenPI's own converter in the training environment:

```bash
python /path/to/openpi/examples/convert_jax_model_to_pytorch.py \
  --checkpoint-dir /data/pi05_base \
  --config-name pi05_libero --precision float32 \
  --output-path /data/pi05_base_pytorch
```

Here `pi05_libero` selects the downstream architecture and data configuration;
it does not select the source weights. The supported configuration uses action
horizon 10, padded action dimension 32 and `discrete_state_input=False`.

Download the LeRobot `physical-intelligence/libero` dataset into
`$HF_LEROBOT_HOME/physical-intelligence/libero`. The tested dataset revision is
`a4336d589d589045d1c56423ffdf3b88a0e19b1f` (1,693 episodes, 273,465 frames,
40 tasks). To pin that revision in the training loader, create
`/data/libero-source.json` containing:

```json
{"repo_id": "physical-intelligence/libero", "revision": "a4336d589d589045d1c56423ffdf3b88a0e19b1f"}
```

Compute statistics from the demonstrations and prepare the bundle/index:

```bash
python scripts/compute_pi05_norm_stats.py \
  --dataset "$HF_LEROBOT_HOME/physical-intelligence/libero" \
  --output /data/libero-stats
python scripts/prepare_pi05_libero.py \
  --checkpoint /data/pi05_base_pytorch \
  --source gs://openpi-assets/checkpoints/pi05_base \
  --dataset-source /data/libero-source.json \
  --norm-stats /data/libero-stats/norm_stats.json \
  --out /data/pi05-training --manifest /data/libero.jsonl
```

Statistics use OpenPI's `RunningStats` and episode-end-padded action chunks.
The JSONL contains dataset indices; OpenPI handles task prompts, image transforms,
normalization, padding and tokenization at load time. The bundle retains the
training statistics for export and inference. The source URI is a declaration,
not proof of download authenticity. An optional `--provenance` JSON can provide
`source_uri` and `converted_weights_sha256`; supplied weight hashes are verified.

## Train and resume

Run one driver in the training environment. For an existing Ray cluster, set
`RAY_ADDRESS` to its head address. Bundle, dataset, manifest and checkpoint paths
must be accessible from every actor with the same training environment.

```bash
python scripts/run_diffusion_sft_pi05.py \
  --bundle /data/pi05-training --manifest /data/libero.jsonl \
  --save /data/pi05-run --nodes 1 --gpus 8 \
  --batch-size 256 --micro-batch-size 4 --steps 30000 --save-interval 500 \
  --lr 5e-5 --min-lr 5e-5 --lr-warmup-init 4.999500049995001e-9 \
  --lr-warmup-iters 10000 --lr-decay-iters 1000000 --lr-decay-style cosine \
  --weight-decay 1e-10 --adam-beta1 0.9 --adam-beta2 0.95 --adam-eps 1e-8 \
  --clip-grad 1 --seed 42 --rollout-seed 42
```

`--gpus` is the number of GPUs per node. Global batch size must divide evenly
across all ranks; additional miles arguments pass through. `--dry-run` prints
the command without loading dependencies or starting workers. The example uses
the OpenPI PyTorch update scale and schedule, with fp32 FSDP execution and no EMA.
It is not a bitwise reproduction of the JAX trainer.

Resume with the original `--bundle`, `--load /data/pi05-run`, and a cumulative
`--steps` target. The adapter restores model, optimizer, scheduler and dataset
cursor; missing required state or failed restoration raises an error rather
than silently restarting. Changing topology or microbatch size changes the
seeded noise/augmentation streams. Multi-node configuration is supported by the
launcher; multi-node full-model execution still needs cluster validation.

The FSDP plan wraps `GemmaMLP`, `GemmaRMSNorm` and `SiglipEncoderLayer`: OpenPI's
joint attention calls decoder children directly, bypassing the decoder block's
forward. Tied embeddings stay in the root group. OpenPI returns unreduced MSE;
the adapter averages action dimensions and sums samples for miles' existing
accumulation/reduction contract, including padded action dimensions.

## Export, serve and evaluate

Export is CPU-only and checks full-model keys, shapes and tied-weight aliases:

```bash
python scripts/export_pi05.py \
  --ckpt-dir /data/pi05-run/iter_0030000 \
  --base-bundle /data/pi05-training --out /data/pi05-export
```

Prepare a local tokenizer in the training environment from OpenPI's cached
`paligemma_tokenizer.model` to avoid SGLang's default gated tokenizer download:

```python
from transformers import GemmaTokenizer
GemmaTokenizer(vocab_file="/path/to/paligemma_tokenizer.model").save_pretrained("/data/tokenizer")
```

Create `/data/serving.json`:

```json
{"tokenizer_name":"/data/tokenizer","materialize_dtype":"fp32","enable_autocast":false,"enable_prefix_cuda_graph":false,"enable_action_cuda_graph":false}
```

Start the server in its separate SGLang environment:

```bash
NVIDIA_TF32_OVERRIDE=0 sglang serve /data/pi05-export \
  --model-type diffusion --num-gpus 1 --host 127.0.0.1 --port 30000 \
  --attention-backend torch_sdpa --pipeline-config-path /data/serving.json \
  --disable-autocast --allow-cudnn-tf32 false
```

Run the evaluator in the simulation environment:

```bash
python scripts/eval_pi05_libero.py \
  --libero-checkout /path/to/LIBERO --bundle /data/pi05-export \
  --endpoint http://127.0.0.1:30000 \
  --suite libero_spatial --trials 50 --output /data/eval-spatial.json
```

Use `--task-id 0` for one task, `--video-dir` to record episodes, or `--resume`
to continue an interrupted evaluation with matching weights and protocol.
The client sends explicit OpenPI tokens, camera masks and noise, then applies
the bundle's output transforms to produce seven-dimensional LIBERO actions.
Reports record per-episode outcomes, initial-state hashes and seeds. Exceptions
abort evaluation instead of being counted as policy failures. Compare models
using identical suites, initial states, seeds, denoising and replanning settings.
