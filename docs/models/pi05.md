# π₀.₅ supervised fine-tuning

This integration implements π₀.₅ training through miles' existing `train_sft.py`,
Ray actors and FSDP2 backend. It supports full-parameter fp32 SFT, checkpoint
resume and full-model export. LoRA, sequence parallelism, mixed precision and
online inference-server weight updates are not supported.

## Environment and inputs

The native model runs on unmodified Transformers 5.12.1 and Torch 2.11.0,
matching miles' default versions. It does not import OpenPI or SGLang.
`requirements-pi05-train.txt` provides a Python 3.12 training/data profile with
Diffusers 0.41.0 and datasets 4.4.2, also matching miles. Do not apply OpenPI's
`transformers_replace` patches in this environment.

The default LIBERO data hook still reuses official OpenPI transforms and LeRobot.
Install miles, OpenPI, its `openpi-client`, and LeRobot with `--no-deps` after
installing the profile: their upstream metadata pins older model dependencies.
This is a validated data-only reuse, not a claim that OpenPI's own PyTorch model
runs unchanged on Transformers 5. Tested data-tool revisions:

- OpenPI: `215abfb217dbac7d5f1273282331b9b1866c0479`
- LeRobot: `0cf864870cf29f4738d3ade893e6fd13fbd7cdb5`

The default data hook uses OpenPI's `pi05_libero` data configuration and
LeRobot `physical-intelligence/libero`. This configuration name selects the
architecture and input transforms, **not pretrained weights**. For base-model
fine-tuning, supply the official `pi05_base` weights converted using OpenPI's
`examples/convert_jax_model_to_pytorch.py` with `--config-name pi05_libero
--precision float32`. Dataset download, statistics computation and simulation
are separate workflows.

`--hf-checkpoint` points to this input bundle:

```text
bundle/
  model.safetensors
  miles_pi05.json
  assets/physical-intelligence/libero/norm_stats.json
```

`model.safetensors` must use OpenPI parameter names and tied-weight metadata.
`norm_stats.json` contains OpenPI action/state statistics from the training
data, including quantiles. A minimal `miles_pi05.json` is:

```json
{
  "version": 1,
  "config_name": "pi05_libero",
  "model": {
    "pi05": true,
    "paligemma_variant": "gemma_2b",
    "action_expert_variant": "gemma_300m",
    "action_horizon": 10,
    "action_dim": 32,
    "max_token_len": 200,
    "discrete_state_input": false
  }
}
```

Optional `dataset_episodes` selects a nonempty list of distinct episode indices;
`dataset_source.revision` pins the LeRobot revision. The JSONL manifest must use
the resulting dataset's row order, with each row containing a real task prompt
and its index, for example:

```json
{"prompt": "pick up the red cup", "metadata": {"openpi_index": 0}}
```

Resolve prompts from the dataset's `task_index` and task metadata using OpenPI's
`PromptFromLeRobotTask`. The data hook loads observation/action chunks by index,
using OpenPI's normalization, image transforms, padding and tokenization.
A local read-only dataset view converts datasets 4 columns to the tensor lists
expected by the pinned LeRobot version; it does not modify installed packages.
Bundles, datasets and manifests must be accessible to all actors.

## Train and resume

Run from the miles checkout. Set `RAY_ADDRESS` for an existing Ray cluster.
This small command illustrates the required hooks; choose batch size, step
count and optimizer settings for your training run.

```bash
python train_sft.py \
  --hf-checkpoint /data/pi05-bundle --diffusion-model-family pi05 --diffusion-task vla \
  --train-only --train-backend fsdp --loss-type sft_loss \
  --update-weight-target-module policy --fsdp-supervised-streams action \
  --fsdp-master-dtype fp32 --fsdp-reduce-dtype fp32 --diffusion-forward-dtype fp32 \
  --diffusion-guidance-scale 1 --gradient-checkpointing \
  --rollout-function-path miles.rollout.pi05_rollout.generate_rollout \
  --custom-prepare-train-batch-path miles.backends.fsdp_utils.models.pi05.loss.prepare_batch \
  --custom-loss-function-path miles.backends.fsdp_utils.loss_hub.sft.sft_loss_formula \
  --custom-convert-samples-to-train-data-path miles.rollout.sft_rollout.convert_samples_to_train_data \
  --custom-rollout-log-function-path miles.rollout.sft_rollout.log_rollout_data \
  --prompt-data /data/train.jsonl --input-key prompt --rollout-shuffle \
  --rollout-batch-size 8 --global-batch-size 8 --micro-batch-size 1 \
  --n-samples-per-prompt 1 --num-rollout 10 --lr 5e-5 \
  --actor-num-nodes 1 --actor-num-gpus-per-node 2 --num-gpus-per-node 2 \
  --save /data/pi05-run --save-interval 10 --log-loss-sigma-bucket 0
```

The manifest must contain at least one rollout batch, and global batch size must
be divisible by the total training GPU count. Compatible hooks can be replaced
through the existing path arguments. Resume with the original input bundle,
`--load /data/pi05-run`, and a cumulative `--num-rollout` target.
The shared loader restores model, optimizer, scheduler, RNG and dataset cursor;
an explicit load fails if required state is missing or corrupt. `--no-load-optim`
skips optimizer state (an existing scheduler is still restored), and
`--no-load-rng` skips RNG restoration.

## Training boundary and export

The prepare hook samples OpenPI noise/time and builds noisy actions and velocity
targets. `Pi05Policy` specializes conditional RMS normalization, gated residuals,
time embeddings and joint prefix/action attention on top of stock Transformers
SigLIP, Gemma projections and MLPs. It returns velocity through the normal model
call, with gradients flowing through both the prefix and action expert. The shared SFT loss averages over action
dimensions, including padding, and sums samples for miles' existing gradient
accumulation/reduction. It performs no model call or optimizer update.

FSDP wraps `SiglipEncoderLayer`, `GemmaMLP` and `Pi05RMSNorm`: the joint
attention bypasses the decoder block forward. Tied embeddings remain together
in the root FSDP group. Noise/time and image augmentation use separate rank-local
seeded streams; this does not reproduce the earlier loss-returning adapter's
random trajectory bit for bit. Two-rank reduced-model gradient equivalence has
been checked, including rank-0/meta loading, an optimizer step and DCP restore.
The full `pi05_base` model was also compared against official OpenPI forward/backward
results and completed one two-GPU AdamW update on real LIBERO inputs. These checks
establish numerical and integration correctness, not convergence or speedup;
multi-node execution and long training runs still need validation.

Checkpoint creation uses the existing miles DCP implementation. Export on CPU:

```bash
python scripts/export_pi05.py \
  --ckpt-dir /data/pi05-run/iter_0000010 \
  --base-bundle /data/pi05-bundle --out /data/pi05-export
```

Export checks keys, shapes and tied aliases, preserves bundle metadata and
normalization assets, and writes `model.safetensors` plus SGLang-compatible
`config.json`. It refuses to overwrite an existing output. The resulting bundle
can be loaded for further training or passed to an external inference client;
simulation evaluation is outside this integration.

## Implementation references

The architecture, augmentation and objective follow
[official OpenPI](https://github.com/Physical-Intelligence/openpi/tree/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/models_pytorch).
The native integration follows the same model-specific adaptation approach as
[SGLang's π₀.₅ core](https://github.com/sgl-project/sglang/blob/6393e66b8649b4e6e22f2d94a933e69059192900/python/sglang/multimodal_gen/runtime/models/vlas/pi05_core.py).
Training uses differentiable PyTorch attention and existing miles FSDP calls;
inference KV caches, CUDA graphs and inference-only kernels are outside its scope.
Weight names remain OpenPI-compatible, including tied embedding aliases, so
export uses the existing SGLang OpenPI weight mapping without another format.
