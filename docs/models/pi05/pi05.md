## 1. Model and integration

π₀.₅ is a vision-language-action model. Miles uses its native model implementation,
`MilesModelBackend`, the shared SFT loss, FSDP2 and DCP checkpoints. Training uses
unmodified Transformers 5.12.1. The optional [LIBERO plugin](../../../plugins/libero/)
contains data preparation, OpenPI transforms, a training launcher and simulator evaluation.
The core model does not import LIBERO, LeRobot or OpenPI.

| Property | Value |
|---|---|
| Family / task / component | `pi05` / `vla` / `policy` |
| Training | Full-parameter FP32, DP/FSDP2, gradient checkpointing, eager attention |
| Supervision | `action`; `x_t = t * noise + (1 - t) * actions`, target `noise - actions` |
| Unsupported | LoRA, mixed precision, sequence parallelism, online serving weight updates |

**Recipe status:** [○ NV — Not verified](../../user-guide/recipe-verification.md#nv).
The commands below define the full workflow; a complete 30,000-step training curve
is not established by the short regression checks. A completed evaluation is not
itself evidence that a newly initialized or briefly trained policy has converged.

## 2. Install from the checkout

Use Ubuntu, Python 3.12 and NVIDIA GPUs with a driver compatible with the selected
Torch CUDA wheels. Conversion needs substantial CPU RAM for materializing the model.
Allow disk space for demonstrations, base weights and multiple full optimizer checkpoints.
Choose the GPU count and microbatch size for your own environment and available memory.

Run from the **root of your Miles checkout**. All plugin code is included in the
repository; no files from a developer's local artifacts directory are required.
`local/` is ignored by Git and holds downloaded dependencies, environments and results.

```bash
# Ubuntu system libraries; install with sudo if necessary.
apt-get update
apt-get install -y build-essential python3-dev curl ca-certificates git ffmpeg \
  libegl1 libgl1 libglib2.0-0 libglfw3 libosmesa6
# Official uv installer: https://docs.astral.sh/uv/getting-started/installation/
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"

export PI05_WORK="$PWD/local/pi05-libero"
bash plugins/libero/setup.sh train "$PI05_WORK"
bash plugins/libero/setup.sh eval "$PI05_WORK"
bash plugins/libero/setup.sh serve "$PI05_WORK"
source plugins/libero/env.sh "$PI05_WORK"
```

The setup script pins OpenPI, LeRobot, LIBERO and SGLang source revisions and creates
**two environments**:

| Interpreter | Purpose |
|---|---|
| `$PI05_WORK/envs/train/bin/python` | Native Miles training, data/conversion tools and LIBERO simulation |
| `$PI05_WORK/envs/serve/bin/sglang` | SGLang action server, with its own Torch/Transformers requirements |

OpenPI and LeRobot are installed with `--no-deps` against the plugin's selected
training/data requirements. Their upstream model dependency pins are not the model
runtime used here. Do not copy `transformers_replace` into either environment.
The serving requirements cover the π₀.₅ diffusion endpoint with `torch_sdpa`, not
SGLang's unrelated LLM/audio features. The plugin does not replace the repository's
general dependency profile for other model families.

`setup.sh eval` downloads the pinned [LIBERO simulator](https://github.com/Lifelong-Robot-Learning/LIBERO)
including task definitions, initial states and assets. Its old top-level requirements
are replaced by the selected simulation dependencies, including robosuite 1.4.1 and
MuJoCo 3.1.6. Training demonstrations are downloaded separately in the next section.

In **each new terminal**, return to the checkout and run:

```bash
source plugins/libero/env.sh "$PWD/local/pi05-libero"
```

Use the same work-directory argument if you chose another location. Keep the source
checkout in place because these are editable installs. For multi-node training, all
actors need the same code/environment and shared absolute dataset/checkpoint paths;
set `RAY_ADDRESS` to your configured cluster. The single-node commands use Ray locally.

## 3. Download and prepare the base model and demonstrations

The initializer is **`gs://openpi-assets/checkpoints/pi05_base`**, not pi05_libero
fine-tuned weights. Conversion reuses the pinned [OpenPI tensor mapping](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/examples/convert_jax_model_to_pytorch.py)
and materializes Miles' native model without OpenPI's patched PyTorch model.
`pi05_libero` names the downstream architecture/data configuration only: action
horizon 10, padded action dimension 32, and `discrete_state_input=False`.

```bash
"$PI05_WORK/envs/train/bin/python" -m pi05_tools.convert_base \
  --openpi-checkout "$PI05_WORK/third_party/openpi" \
  --output "$PI05_WORK/base-converted"

"$PI05_WORK/envs/train/bin/python" -m pi05_tools.download_data \
  --source-output "$PI05_WORK/dataset-source.json"

"$PI05_WORK/envs/train/bin/python" -m pi05_tools.compute_norm_stats \
  --dataset "$HF_LEROBOT_HOME/physical-intelligence/libero" \
  --output "$PI05_WORK/libero-stats"

"$PI05_WORK/envs/train/bin/python" -m pi05_tools.prepare_libero \
  --checkpoint "$PI05_WORK/base-converted" \
  --provenance "$PI05_WORK/base-converted/provenance.json" \
  --dataset-source "$PI05_WORK/dataset-source.json" \
  --norm-stats "$PI05_WORK/libero-stats/norm_stats.json" \
  --out "$PI05_WORK/base-bundle" --manifest "$PI05_WORK/train.jsonl"
```

Conversion downloads into `$OPENPI_DATA_HOME`; `--checkpoint` can reuse an existing
**official pi05_base JAX directory**. The dataset is `physical-intelligence/libero`,
revision `a4336d589d589045d1c56423ffdf3b88a0e19b1f`: 1,693 episodes, 273,465 frames,
40 tasks. The JSONL contains frame indices and real task instructions, not image
copies. The data loader supplies image transforms, tokenization, normalized/padded
actions and episode-end-padded action chunks. Statistics cover the complete dataset
and travel with the exported weights so evaluation uses the same transforms.

Preparation/conversion outputs must be new paths. Dataset downloads can be rerun;
use the same revision and cache environment. For offline workers, finish downloading
the dataset and tokenizer (`prepare_serving` in section 4) before setting
`HF_HUB_OFFLINE=1`. To reuse an existing copy of the pinned dataset, set
`HF_LEROBOT_HOME` to its parent cache directory **after** sourcing `env.sh`;
`$HF_LEROBOT_HOME/physical-intelligence/libero` must contain the complete snapshot.

## 4. Train, resume and export

The following uses the OpenPI PyTorch recipe's update scale and learning-rate
schedule, with Miles FP32 FSDP execution and no EMA. It is not a bitwise reproduction
of the JAX trainer. Global batch size must be divisible by the total GPU count.

```bash
export STEPS=30000
: "${GPUS:?Set GPUS to the training GPU count available in your environment}"
BATCH=256
MICRO=4
SAVE=500

# For an installation smoke run, use STEPS=2, BATCH=$GPUS, MICRO=1, SAVE=1.
# Ensure the model fits your selected topology. This checks execution, not convergence.
train_args=(
  --bundle "$PI05_WORK/base-bundle" --manifest "$PI05_WORK/train.jsonl"
  --save "$PI05_WORK/train" --nodes 1 --gpus "$GPUS"
  --batch-size "$BATCH" --micro-batch-size "$MICRO" --steps "$STEPS" --save-interval "$SAVE"
  --lr 5e-5 --min-lr 5e-5 --lr-warmup-init 4.999500049995001e-9
  --lr-warmup-iters 10000 --lr-decay-iters 1000000 --lr-decay-style cosine
  --weight-decay 1e-10 --adam-beta1 0.9 --adam-beta2 0.95 --adam-eps 1e-8
  --clip-grad 1 --seed 42 --rollout-seed 42
)
"$PI05_WORK/envs/train/bin/python" -m pi05_tools.run_libero_sft "${train_args[@]}"
```

`--dry-run` prints the underlying `train_sft.py` command. The launcher explicitly
selects the plugin's rollout hook and Miles' existing batch preparation, SFT loss
and logging hooks. Gradient accumulation is handled by Miles. The data producer
uses the resumable global JSONL cursor.

To resume, reconstruct the same `train_args` above with the desired **cumulative**
step target, then add `--load`. Use the original base bundle, not an exported policy:

```bash
"$PI05_WORK/envs/train/bin/python" -m pi05_tools.run_libero_sft \
  "${train_args[@]}" --load "$PI05_WORK/train"
```

Resume restores model, optimizer, scheduler, RNG and dataset cursor. Missing required
state is an error. Changing topology or microbatch size changes the seeded noise and
augmentation streams. Multi-node full-model execution needs cluster validation.

After training completes, export the matching step (CPU operation):

```bash
CHECKPOINT="$PI05_WORK/train/iter_$(printf '%07d' "$STEPS")"
"$PI05_WORK/envs/train/bin/python" scripts/export_pi05.py \
  --ckpt-dir "$CHECKPOINT" --base-bundle "$PI05_WORK/base-bundle" \
  --out "$PI05_WORK/export-step-$STEPS"

"$PI05_WORK/envs/train/bin/python" -m pi05_tools.prepare_serving \
  --output "$PI05_WORK/serving"
```

Export validates keys, shapes and tied aliases and preserves normalization assets.
Each export needs a new output path. Serving preparation downloads the public
PaliGemma tokenizer, avoiding SGLang's default gated tokenizer download. Run it once;
reuse `serving/serving.json` for later checkpoints at the same absolute work path.

## 5. Start SGLang and run LIBERO simulation

In a terminal with the work environment sourced, choose the completed exported step:

```bash
export STEPS=30000  # use 2 for the smoke checkpoint above
CUDA_VISIBLE_DEVICES=0 NVIDIA_TF32_OVERRIDE=0 \
"$PI05_WORK/envs/serve/bin/sglang" serve "$PI05_WORK/export-step-$STEPS" \
  --model-type diffusion --num-gpus 1 --host 127.0.0.1 --port 30000 \
  --master-port 30010 --scheduler-port 30020 \
  --attention-backend torch_sdpa --pipeline-config-path "$PI05_WORK/serving/serving.json" \
  --disable-autocast --allow-cudnn-tf32 false
```

Wait for readiness (`curl --fail http://127.0.0.1:30000/health`). Keep this terminal
running. HTTP port 30000, broker port 30001, master port 30010 and scheduler port
30020 must be free; choose distinct groups when serving multiple models.

In a second terminal, source `env.sh` and use the **training/simulation** interpreter:

```bash
export STEPS=30000
MUJOCO_GL=egl MUJOCO_EGL_DEVICE_ID=0 PYOPENGL_PLATFORM=egl CUDA_VISIBLE_DEVICES=0 \
"$PI05_WORK/envs/train/bin/python" -m pi05_tools.eval_libero \
  --libero-checkout "$PI05_WORK/third_party/LIBERO" \
  --bundle "$PI05_WORK/export-step-$STEPS" --endpoint http://127.0.0.1:30000 \
  --suite libero_spatial --task-id 0 --trials 50 --seed 7 \
  --num-steps 10 --replan-steps 5 --wait-steps 10 \
  --output "$PI05_WORK/eval-step-$STEPS-task0.json"
```

This runs the single task “pick up the black bowl between the plate and the ramekin
and place it on the plate,” with 50 initial states and a 220-action limit per episode.
The policy requests action chunks from SGLang, applies the saved inverse transforms,
and steps the LIBERO simulator. Success is the simulator's task-success signal.
The evaluator creates an isolated LIBERO config automatically; no interactive
`~/.libero` setup or training-demo download from LIBERO's old scripts is needed.
`MUJOCO_EGL_DEVICE_ID` follows EGL device enumeration; `CUDA_VISIBLE_DEVICES`
does not necessarily renumber that list. Robosuite 1.4.1 also requires that ID
to appear in the simulator's `CUDA_VISIBLE_DEVICES`. The HTTP policy server can
use a different GPU from the simulator.

- Remove `--task-id 0` to evaluate all tasks in `libero_spatial` (50 trials each).
  Other suites: `libero_object`, `libero_goal`, `libero_10`, `libero_90`.
- Add `--video-dir "$PI05_WORK/videos-step-$STEPS"` to save MP4s in a new directory.
- For a quick environment check, use `--trials 1 --max-steps 10` and a different
  output path. Such a report is marked `smoke` and is not a benchmark success rate.
- Use `--resume` to continue an interrupted evaluation with the same bundle and
  protocol. The existing video directory can be reused: completed episodes are
  skipped and partial videos for interrupted episodes are replaced. A completed
  output path cannot be overwritten.

Results contain checkpoint metadata, protocol, per-episode seeds/initial-state hashes,
steps and success rate. HTTP/model/simulator errors abort the run instead of counting
as task failures. Compare policies with the same suite, initial states, seeds,
denoising and replanning settings. Stop the foreground server with Ctrl-C when done.

## 6. Custom data adapters

For other datasets, keep the same core model and replace the optional plugin hook.
`--hf-checkpoint` is a bundle with OpenPI-compatible `model.safetensors` (tied-weight
metadata included) and `miles_pi05.json`, for example:

```json
{
  "version": 1,
  "model": {
    "pi05": true, "paligemma_variant": "gemma_2b", "action_expert_variant": "gemma_300m",
    "action_horizon": 10, "action_dim": 32, "max_token_len": 200
  }
}
```

Optional `data_adapter` metadata and `assets` paths relative to `assets/` describe
adapter-owned transforms. Declared assets must exist; export preserves them.
A [rollout hook](../../user-guide/customization.md) supplies each sample's
`train_metadata["sft_pair"] = {"observation": observation, "actions": actions}`.

| Input | Contract before batching |
|---|---|
| `observation.image` | Exactly `base_0_rgb`, `left_wrist_0_rgb`, `right_wrist_0_rgb`; each RGB image is HWC or CHW, 224×224, uint8 `[0,255]` or float32 `[-1,1]` |
| `observation.image_mask` | Same keys, scalar bool per camera; missing cameras need a valid dummy image and False mask |
| `observation.tokenized_prompt` / `tokenized_prompt_mask` | int32/int64 token IDs within the vocabulary / bool mask, both `[T]`, `1 <= T <= max_token_len` |
| `observation.state` (optional) | Finite float32/float64 `[action_dim]`; context only, not embedded by the forward |
| `actions` | Finite float32 `[action_horizon, action_dim]`, already normalized and padded |

Adapters own resizing, camera mapping, tokenization/state encoding, action alignment,
normalization and padding. Corresponding layouts, token lengths and keys must match
within a batch. Raw `state` alone does not condition the model; encode it in prompt
tokens when required. Loss includes padded action dimensions. Supply images before
random augmentation; the model applies training augmentation. Inference adapters
must use matching input and inverse action transforms.


The plugin launcher is a concrete example of selecting these existing hooks:

```text
--custom-prepare-train-batch-path miles.backends.fsdp_utils.models.pi05.loss.prepare_batch
--custom-loss-function-path miles.backends.fsdp_utils.loss_hub.sft.sft_loss_formula
--custom-convert-samples-to-train-data-path miles.rollout.sft_rollout.convert_samples_to_train_data
--custom-rollout-log-function-path miles.rollout.sft_rollout.log_rollout_data
```
