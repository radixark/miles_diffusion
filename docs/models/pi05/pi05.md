## 1. Model introduction

π₀.₅ is a vision-language-action model. The native backend uses miles' shared SFT
loss, FSDP2 and DCP checkpoints with the normal miles dependencies; it does not
require OpenPI or patched Transformers. Dataset adapters and simulator evaluation
remain external. Training and SGLang inference can run in separate environments.

## 2. Family config

Registered in `miles/backends/fsdp_utils/configs/pi05.py`:

| Property | Value |
|---|---|
| Family / task / component | `pi05` / `vla` / `policy` |
| Training | Full-parameter FP32, DP/FSDP2, gradient checkpointing, eager attention |
| Supervision | `action`; `x_t = t * noise + (1 - t) * actions`, target `noise - actions` |
| Unsupported | LoRA, mixed precision, sequence parallelism, online serving weight updates |

`--hf-checkpoint` is a directory containing OpenPI-compatible `model.safetensors`
(with tied-weight metadata) and `miles_pi05.json`, for example:

```json
{
  "version": 1,
  "model": {
    "pi05": true, "paligemma_variant": "gemma_2b", "action_expert_variant": "gemma_300m",
    "action_horizon": 10, "action_dim": 32, "max_token_len": 200
  }
}
```

Set dimensions to match the checkpoint. Optional `data_adapter` metadata and
`assets` (file paths relative to `assets/`) describe external transforms; declared
files must exist. Export preserves the metadata and optional assets directory.

## 3. Launch

**Status:** [○ NV — Not verified](../../user-guide/recipe-verification.md#nv).
No complete training curve is documented for this integration.

Use an external [rollout hook](../../user-guide/customization.md) returning each
sample's `train_metadata["sft_pair"] = {"observation": observation, "actions": actions}`:

| Input | Contract before batching |
|---|---|
| `observation.image` | Exactly `base_0_rgb`, `left_wrist_0_rgb`, `right_wrist_0_rgb`; each RGB image is HWC or CHW, 224×224, uint8 `[0,255]` or float32 `[-1,1]` |
| `observation.image_mask` | Same keys, scalar bool per camera; missing cameras need a valid dummy image and False mask |
| `observation.tokenized_prompt` / `tokenized_prompt_mask` | int32/int64 token IDs within the vocabulary / bool mask, both `[T]`, `1 <= T <= max_token_len` |
| `observation.state` (optional) | Finite float32/float64 `[action_dim]`; context only, not embedded by the forward |
| `actions` | Finite float32 `[action_horizon, action_dim]`, already normalized and padded |

Adapters own resizing, camera mapping, tokenization/state encoding, action alignment,
normalization and padding. Corresponding layouts, token lengths and keys must match
within a batch. Raw `state` alone does not condition the model; encode it in prompt
tokens when required. Loss includes padded action dimensions. Supply images before
random augmentation; the model applies training augmentation. Inference adapters
must use matching input and inverse action transforms.

Use `train_sft.py` with your normal GPU, batch, optimizer, data-source and checkpoint
arguments, plus these model-specific settings and existing hooks:

```text
--diffusion-model-family pi05 --diffusion-task vla
--train-only --train-backend fsdp --loss-type sft_loss
--update-weight-target-module policy --fsdp-supervised-streams action
--fsdp-master-dtype fp32 --fsdp-reduce-dtype fp32 --diffusion-forward-dtype fp32
--diffusion-guidance-scale 1 --gradient-checkpointing --log-loss-sigma-bucket 0
--rollout-function-path my_adapter.rollout.generate_rollout
--custom-prepare-train-batch-path miles.backends.fsdp_utils.models.pi05.loss.prepare_batch
--custom-loss-function-path miles.backends.fsdp_utils.loss_hub.sft.sft_loss_formula
--custom-convert-samples-to-train-data-path miles.rollout.sft_rollout.convert_samples_to_train_data
--custom-rollout-log-function-path miles.rollout.sft_rollout.log_rollout_data
--n-samples-per-prompt 1
```

## 4. Resume and export

Resume with the original bundle, `--load` and a cumulative `--num-rollout` target.
Required checkpoint state must be complete; use a resumable data-source cursor.
See the [checkpoint flags](../../user-guide/cli-reference.md) for load/save options.

```bash
python scripts/export_pi05.py --ckpt-dir /data/run/iter_0000010 \
  --base-bundle /data/pi05-bundle --out /data/pi05-export
```

Export consolidates DCP weights, checks keys/shapes/tied aliases and writes a
SGLang-compatible `config.json`. The output directory must not already exist.
